# OpenWrt 25.12.6 rebase — status and plan

Branch: `openwrt-25.12` (not merged, nothing released).

## What works

- 25.12.6 SDK and Image Builder for `bcm53xx/generic` downloaded and extracted.
- Base image builds for `asus_rt-ac88u` with the streamer package list
  (12 MB `.trx`, kernel 6.12.112, gcc 14.3.0, musl).
- Package names are unchanged (`mpd-mini`, `upmpdcli`, `kmod-usb-audio`,
  `kmod-fs-cifs`, `libopenssl`, `libpcre2`, LuCI modules).
- `apk` replaces `opkg`, but the Image Builder still accepts the same
  `PACKAGES=` syntax.

## Image Builder gotchas

1. **`apk` requires root ownership.** As a normal user it fails with hundreds of
   `failed to preserve owner` errors. Run:

   ```sh
   unshare -r make image PROFILE=asus_rt-ac88u PACKAGES="..." FILES="$PWD/ovl"
   ```

   (`fakeroot` works too, but `unshare -r` is cleaner.)
2. **Do not delete `build_dir`.** The tarball ships prebuilt
   `build_dir/.../linux-bcm53xx_generic/*-kernel.bin`. Removing the directory
   destroys them and the build fails with
   `No rule to make target '...-kernel.bin'`. Re-extract the tarball to recover.
3. The image is ~12 MB without the custom binaries, versus 14 MB on 24.10.

## Blockers for the custom binaries

**MPD**: the 25.12 `mpd-full`/`mpd-mini` packages (0.23.16) are built with
`-Ddsd=false`, so they cannot drive the DAC in DoP mode. A custom build is
still required. The clean SDK has no dev libraries: `libasound`, `libFLAC`,
`libmad`, `libfaad`, `libopus`, `libvorbisidec`, `libfmt`, `libmpdclient` and
the ALSA headers are all missing from `staging_dir/target-*`.

Two options:

1. Build through the SDK feed system: `scripts/feeds update`, install `mpd`,
   patch `-Ddsd=true`, let the SDK build all dependencies, then copy the
   resulting binary. Slow but reproducible.
2. Cross-build dependencies manually (fmt 12, ALSA/FLAC/etc. headers) into a
   local prefix. More control, more work.

**myMPD**: not packaged in the 25.12 feeds, so it must still be cross-built.
It needs `libmpdclient` headers, OpenSSL 3.5, PCRE2 and the `-Werror` patch
already in the repository.

## ABI notes

The 24.10 binaries use `libfmt.so.11`; 25.12 ships `libfmt.so.12`. The MPD
binary will not load without a rebuild (or shipping the old libfmt, which is
not recommended). Other sonames (`libFLAC.so.12`, `libasound.so.2`,
`libmpdclient.so.2`, `libssl.so.3`) are compatible in name but must be rebuilt
for gcc 14 to avoid ABI surprises.

## Suggested sequence

1. `scripts/feeds update -a && scripts/feeds install mpd libmpdclient fmt`
2. Patch the MPD package to `-Ddsd=true` (or build the source directly with the
   SDK staging tree after the dependencies are built).
3. Rebuild myMPD against the 25.12 staging tree; apply the existing patch.
4. Update `build/mpd-cross.txt` and `build/mympd-toolchain.cmake` to the gcc 14
   paths; regenerate `ovl/etc/init.d/mpd` from the 25.12 package (it may have
   changed).
5. Re-run `verify.sh`, build the image, test on hardware **before** replacing
   v1.2. Expect network/DSA changes in 25.12; keep a serial or backup route.
6. Only then tag a 25.12-based release (e.g. v2.0) and update the README’s
   version table.

## Do not flash yet

The base 25.12 image has no custom MPD/myMPD and no streamer configuration.
It is a build-validation artifact only.

## SDK feed attempt (2026-10-30)

Steps taken:

```sh
./scripts/feeds update -a
./scripts/feeds install mpd libmpdclient
sed -i 's/-Ddsd=false/-Ddsd=true/' feeds/packages/sound/mpd/Makefile
make defconfig
make package/mpd/compile
```

Results:

- Feed update/install succeeded; `mpd` is patched to `-Ddsd=true`.
- The SDK config reports a recursive `libcurl`/`LIBURL_LDAP` dependency and
  ignores `.config` changes.
- `make package/mpd/compile` builds host tools, then pulls in `avahi`,
  `boost`, `package/kernel/linux`, `openssl` and `cryptodev-linux`; it had not
  reached MPD after ~30 minutes and produced no binary.
- Running the build under `unshare -r` makes host-tool installs fail
  (`bzip2`/`libffi` owner errors). Build as the normal user instead.

Conclusion: the SDK's package target is not a shortcut for a single patched
package. Rebase via the **full OpenWrt buildroot** (checkout `v25.12.6`, patch
`package/feeds/packages/sound/mpd/Makefile`, `make menuconfig`, build the image)
is the more predictable route. The SDK is still useful for validating the
package list and base image.
